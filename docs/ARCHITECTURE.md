# 설계와 후속 구현 범위

## 구조

```text
spreadsheet.fxml → SpreadsheetApp (FXML 컨트롤러, 선택/입력/보기)
    ├── Book (POI 워크북, 수식 캐시, 트랜잭션/실행 취소)
    ├── BookFiles (JSONL, XLSX, CSV, 원자적 저장)
    ├── SheetEdits (상대 참조 채우기, 찾기/바꾸기)
    ├── CellClipboard (범위 값/서식, 복사 시점 계산값, 수식 토큰/참조 정보)
    ├── CellMove (같은 시트 잘라내기, 종속 참조 갱신)
    ├── StructuralEdits (행/열 삽입·삭제, 경계 보호, 참조/병합/레이아웃 이동)
    ├── SaveNotification (포커스를 유지하는 저장 경로 알림)
    └── GitDialog → GitService (서비스 선택, 문서 커밋, push/fetch, 시간 제한)
```

POI 객체는 UI 스레드에 한정한다. Git 작업만 가상 스레드에서 실행하고 결과는 Platform.runLater로 전달한다. 파일 경로를 Git 명령 문자열에 삽입하지 않는다. 모든 파일 지정에는 `--`를 사용하고 커밋에는 `--only`를 사용한다.

## 저장 형식 v1

첫 줄은 type=git-sheet, version=1 헤더다. 그다음 시트 선언, 행 레이아웃, 셀 레코드가 시트/행/열 순서로 나타난다. 스타일을 셀에 직접 기록하여 별도 스타일 ID 재배열 때문에 diff가 확산되지 않게 한다. 빈 기본 셀과 계산 결과 캐시는 생략한다. 파일은 UTF-8/LF이다. JSONL 문법 검증 및 스키마 버전 검사를 수행한다.

이 방식은 셀 스타일 중복으로 파일 크기가 커지는 대신 셀 변경 비교가 간단하다. 대용량 문서에는 시트별 분리와 안정적인 스타일 키가 후속 대안이다. Git merge는 텍스트 병합이며 자동 의미 충돌 해결은 제공하지 않는다.

## 성능 특성

- 그리드가 전체 Excel 셀 객체를 미리 만들지 않는다. 읽기만 한 빈 셀은 모델에 생성하지 않는다.
- 화면은 1,000행 × 52열 창을 사용하고 TableView가 보이는 행만 렌더링한다.
- POI evaluator 캐시는 값 수정 시 무효화한다. UI가 요청하는 셀을 평가한다.
- 범위 서식은 동일 원본 스타일/수정 키의 스타일을 재사용한다.
- 클립보드는 원본 Workbook/Cell 객체나 전체 XLSX를 유지하지 않는다. 선택 셀의 타입 값, 고유 서식만 담은 작은 XLSX, 수식 토큰과 렌더링에 필요한 이름/시트 문자열을 보관한다. 수식 계산 결과는 복사 시점에 고정하며, 붙여넣기마다 토큰을 복제해 상대 참조를 이동한다.
- 실행 취소는 안정적인 XLSX 스냅샷 방식이다. 셀 delta 방식보다 느리므로 큰 문서용 구조가 아니다.
- 저장·로드·화면 필터는 현재 동기 작업이다. 백그라운드 워크북 소유권 이전, 취소 및 진행률은 후속 작업이다.

## 다음 단계와 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 · 편집 품질 | delta 기반 undo, 타입 보존 클립보드, 상대 참조 이동, 전체 범위 정렬 | 대량 붙여넣기/수식 이동 회귀 테스트 및 재계산 정확도 검증 |
| 2 · 구조 편집 | 행/열 삽입·삭제, 드래그 채우기, 병합, 틀 고정 (메뉴 채우기 및 기본 행/열 삽입·삭제 완료) | 모든 참조 수정, undo, 파일 왕복 테스트 |
| 3 · 분석/서식 | 조건부 서식, 유효성 검사, 테이블, 영구 차트, 이름 정의 | Excel 생성 샘플과 왕복 비교, 고급 객체 손실 경고 |
| 4 · 파일/배포 | 백그라운드 I/O, autosave/recovery, jpackage 설치 파일, 서명 | 강제 종료 복구와 플랫폼별 설치 테스트 |
| 5 · Git UX | 브랜치·pull·시각적 셀 diff·충돌 해결 (서버 선택/push/fetch 완료) | 브랜치 충돌 시나리오, 기존 staged 변경 보호 |
| 6 · 고급 Excel | 피벗, 동적 배열 함수, 데이터 연결, 인쇄 | 기능별 호환성 코퍼스와 성능 예산 수립 |

VBA, Power Query, Power Pivot은 독립적인 실행 엔진과 보안 모델이 필요한 큰 영역이다. 전체 Excel 호환성을 선언하려면 별도 장기 개발과 검증이 필요하다.

## 빌드와 화면

Gradle Wrapper 9.4.1과 JDK 25 toolchain을 사용한다. `gradlew build`는 테스트와 배포 ZIP/TAR을 생성하고 `gradlew run`은 앱, `gradlew smokeTest`는 실제 UI 검사를 실행한다. JavaFX 라이브러리를 현재 OS/아키텍처에 맞춰 선택하므로 배포 파일도 해당 플랫폼 전용이다. 메인 화면의 정적 레이아웃은 spreadsheet.fxml에 두고 셀·시트 및 동적 대화상자는 코드에서 생성한다.

병합 표시 책임은 `MergedCellOverlay`에 분리되어 있다. 현재 워크북/시트/선택은 공급자로 읽고, 앵커 선택·편집 및 CSS 생성은 컨트롤러 콜백으로 연결한다. 뷰의 종료 시 대기 중 repaint를 무효화한 뒤 워크북을 닫는다.
